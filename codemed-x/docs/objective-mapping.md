# 評価項目とコア・カリキュラムの対応

## 何をしているか

シミュレータ内の評価項目 `objective_id`（例 `WLF-INT-01`）を、本リポジトリが公開している
**医学教育モデル・コア・カリキュラム（令和4年度改訂版）の `id`** に対応づけている。

```
シミュレータのイベント          objectives.csv                コアカリ (2022/ja/outcomes)
─────────────────────      ────────────────────      ──────────────────────────
objective_id: WLF-INT-01  →  corecurriculum_ids:      →  layer4.csv
                                JkxhhWA                    id=JkxhhWA
                                                           index=CM-01-02-02
                                                           item=患者や家族の話を傾聴し、
                                                                怒りや悲しみ、不安等の
                                                                感情を理解し、共感できる。
```

これにより、演習で得た学習履歴を大学のカリキュラムマップと同じ粒度で集計できる。

## なぜインデックスではなく id で紐づけるか

コアカリには 2 種類の識別子がある（リポジトリ [README](../../README.md) 参照）。

| | インデックス (CM-01-02-02) | id (JkxhhWA) |
|---|---|---|
| 読みやすさ | ○ | × |
| 改訂による変化 | **あり** | なし |

インデックスは連番なので、項目の追加・削除で指し示す先が変わる。
学習履歴は数年にわたって蓄積するため、**`id` を正**とし、インデックスは
人間が読むための補助として併記している。両者の整合は検証スクリプトが確認する。

## objectives.csv の形式

| 列 | 内容 |
|---|---|
| `objective_id` | シミュレータ内の評価項目ID。`AAA-BBB-01` 形式 |
| `scenario_id` | この項目が属するシナリオ |
| `label` | 日本語のラベル（デブリーフィング画面に出す） |
| `category` | `observation` / `communication` / `assessment` / `decision` / `escalation` / `coordination` / `safety` / `documentation` / `knowledge` |
| `corecurriculum_index` | コアカリのインデックス。`;` 区切りで複数可 |
| `corecurriculum_ids` | コアカリの id。`;` 区切り。**index と同じ順序・同じ個数** |
| `external_standard` | 準拠する外部基準（SPIKES、児童福祉法第33条、薬剤師法第24条 等） |

`objective_id` の接頭辞はシナリオに対応する。

| 接頭辞 | シナリオ |
|---|---|
| `WLF-` | ① 相談援助面接 |
| `ACP-` | ② 困難な対話（ACP / SPIKES） |
| `NGT-` | ③ 夜勤・複数患者 |
| `PHM-` | ④ 薬剤師・疑義照会 |
| `GTK-` | ⑤ ゲートキーパー |

## 検証

```bash
python3 codemed-x/tools/validate_codemedx.py
```

以下を機械的に確認する。

1. `objective_id` の書式と重複
2. `corecurriculum_ids` の各 id が `2022/ja/outcomes/layer1〜4.csv` に**実在する**こと
3. 併記した `corecurriculum_index` が、その id の実際のインデックスと一致すること
4. サンプルイベントが JSON Schema に適合し、使っている `objective_id` が
   `objectives.csv` に存在し、かつ `scenario_id` と矛盾しないこと

評価項目を追加・変更したら必ずこれを通すこと。存在しない id を書いても
Unity 側は何も言わずに動いてしまい、集計の段階で初めて壊れていることが分かる。

## Unity への取り込み

`Tools > Codemed-x > 評価項目カタログを CSV から再生成` を実行すると、
`objectives.csv` の内容が `ObjectiveCatalog` アセットへ取り込まれる。

正本を CSV 側に置いている理由:

- コアカリのデータと同じリポジトリ・同じ形式（UTF-8 BOM 付き csv）で管理でき、
  検証スクリプトから直接照合できる。
- シナリオ監修者（教員）が Unity を開かずにレビュー・修正できる。

## 対象範囲についての注意

コアカリは**医学教育**のモデル・コア・カリキュラムである。①（児童福祉・社会福祉）、
③（看護）、④（薬学）、⑤（公衆衛生・ゲートキーパー）は本来それぞれ別の
教育課程に属するため、対応づけは「関連する資質・能力への写像」であって
当該職種の到達目標そのものではない。

各シナリオの一次的な準拠先は `external_standard` 列に明記している
（児童福祉法第33条、SPIKES、薬剤師法第24条、ゲートキーパー養成研修用テキスト等）。
他職種のコア・カリキュラム（薬学教育モデル・コア・カリキュラム、
看護学士課程のコアコンピテンシー等）のデータが本リポジトリに追加された場合は、
`corecurriculum_ids` を多重対応にできる設計にしてある（`;` 区切り）。
