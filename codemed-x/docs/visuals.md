# 背景と登場人物の作り方

「動くもの」ができたあと、見た目をどう作るか。ここは**作り方の選択がいちばん効く**。
選択を誤ると、費用と時間の大半が、学習効果にほとんど寄与しない部分に消える。

## 先に結論

**①②④⑤（対話が主のシナリオ）は 3D 空間を作らないほうがよい。**
360度実写、または 2D の背景 + 立ち絵で十分どころか、むしろ優れている。

理由は 3 つある。

1. **これらのシナリオで学習者が見るべきものは、部屋ではなく相手の顔と間である。**
   3D の部屋を作り込んでも、そこに学習効果はほとんど乗らない。
2. **中途半端な 3D アバターは逆効果になる。** 人間に似ているが少しずれた顔は
   不気味の谷に落ち、共感的な対話の訓練の妨げになる。実写かイラストのほうが安全。
3. **監修サイクルが回らなくなる。** 3D で作り込むほど、監修者の「この言い方は違う」
   という指摘を反映するのに時間がかかる。文言はまだ何度も変わる。

**③（夜勤・複数患者）だけは 3D 空間に意味がある。**
病室の間を移動し、複数の患者を同時に視野に入れることが学習内容そのものだから。

## 選択肢の比較

| | 2D 背景 + 立ち絵 | 360度実写（写真/動画） | 3D 空間 + アバター |
|---|---|---|---|
| 費用感 | 数万円〜（素材購入・生成） | 十数万円〜（撮影・出演） | 数十万〜数百万円 |
| 期間 | 数日 | 2〜4 週間（調整含む） | 2〜6 か月 |
| 臨場感 | 低〜中 | **高**（実物そのもの） | 中〜高（作り込み次第） |
| VR 対応 | × | ○（見回せる） | ○（歩き回れる） |
| 内容の修正 | **即日** | 撮り直しが必要 | 中程度 |
| 向くシナリオ | 全部（試作段階） | ①②④⑤ | ③ |

## 進め方の推奨

### 段階 1: 2D 背景 + 立ち絵（今すぐできる）

`codemed-x/standalone/presentation/SimBackdrop.cs` を使う。
**シナリオ側のスクリプトを一切変更せずに、背景と立ち絵を後ろに描ける。**

1. シーンに空の GameObject を作り、`SimBackdrop` を付ける
2. `Background` に背景画像を割り当てる
3. `Characters` に立ち絵を追加し、`Anchor X` で位置を決める
   （0 = 左端、0.5 = 中央、1 = 右端）
4. 文字が読みにくければ `Dim Amount` を上げる（背景に暗幕が掛かる）

素材が無い段階でも、灰色の板を割り当てればレイアウトだけ先に決められる。

画像の入手先:

- **Unity Asset Store** — 病室・診察室・薬局の背景写真セットが数千円からある
- **写真素材サイト**（PIXTA、Adobe Stock 等）— 日本の医療現場の写真が揃う。
  **人物が写った写真は肖像権の確認が要る**（商用利用可のライセンスを確認する）
- **自分で撮る** — 協力の得られる施設で撮るのが、いちばん確実で安い

立ち絵は、イラストレーターへの発注か、写真から作る（背景を透過処理する）。
研修教材では**イラストのほうが受け入れられやすい**ことが多い。
特定の個人に見えないため、学習者が自分の担当患者に重ねすぎない利点がある。

### 段階 2: 360度実写（①②④⑤ の本命）

対話シナリオの臨場感は、これがもっとも費用対効果が高い。
HMD で見回すと、その場に居る感覚が一気に出る。

**撮影**

- カメラ: Insta360 X 系、RICOH THETA 系（10 万円以下から）
- 演者: **本物の患者を撮らない。** 模擬患者（SP）や俳優を起用する。
  医学教育では模擬患者の養成が広く行われており、協力を得られることが多い
- 場所: 実際の診察室・薬局・家庭を模したセット。
  背景に個人情報（掲示物、カルテ、名札）が写り込まないよう事前に確認する
- 撮り方: 選択肢ごとに反応を撮り分ける。**分岐の数だけ撮影が必要**なので、
  文言を確定してから撮る。ここが最大の落とし穴

生成AIで背景を作る場合のプロンプトは
[`visuals-prompts.md`](visuals-prompts.md) にシナリオ別にまとめてある。

**Unity での表示（コードは不要）**

1. 360度画像を Unity にインポートし、Inspector で `Texture Shape` を `2D`、
   `Wrap Mode` を `Clamp` にする
2. `Assets 右クリック > Create > Material` でマテリアルを作る
3. Shader を **`Skybox/Panoramic`** にし、`Spherical (HDR)` に画像を割り当てる
4. `Window > Rendering > Lighting > Environment > Skybox Material` に設定する

動画の場合は、球体の内側にビデオを投影する（`Video Player` + `Render Texture`）。

### 段階 3: 3D 空間（③ のみ）

夜勤シナリオは、病室の間を移動し、複数の患者を同時に把握することが学習内容なので、
3D 空間が要る。**グレーボックス（灰色の板だけの仮モデル）版は実装済み。**

`codemed-x/standalone/03-nightshift-triage/` に以下がある。

| ファイル | 役割 |
|---|---|
| `SimpleWalker.cs` | WASD + マウスの一人称移動。XR パッケージには依存しない |
| `BedStation.cs` | ベッド・電話・ナースコール共通の「発生すると光り、近づいて [E] で対応する」部品 |
| `NurseStationPhone.cs` | 医師への疑義照会（エスカレーション）用の電話 |
| `Editor/NightShiftHospitalBuilder.cs` | 空のシーンにグレーボックス病棟を自動生成するエディタ拡張 |

使い方: 空のシーンで **Tools > Codemed-x > 夜勤: グレーボックス病棟を生成** を実行し、Play するだけ。

設計上のポイント:

- **3D にしても採点基準が変わらないようにしてある。** `NightShiftSim` に
  `TryAttendTo(taskId)` / `TryOpenEscalationMenu()` という公開 API を用意し、
  IMGUI のボタンも 3D のベッド・電話も、この同じ API を経由する。
  「歩いて操作するとログの形が変わる」ということが起きない。
- **本物のモデルへの差し替えは見た目だけで済む。** `BedStation` / `NurseStationPhone` は
  Cube のメッシュとマテリアルを対象にしているだけなので、購入・発注したモデルに
  差し替えても、近接判定や着手のロジックはそのまま動く。
- IMGUI のタスク一覧・ボタンは残したままにしてある。3D を使わずキーボードだけで
  最後まで進めることもできる（PC 環境や VR 酔いへの配慮が必要な学習者向け）。

本物のモデルに進む場合:

- 病室・病棟のモデル: Unity Asset Store に医療系の環境アセットがある
- アバター（他の患者・スタッフを登場させる場合）: Ready Player Me、VRoid Studio、
  Reallusion Character Creator
- アニメーション: Mixamo（無料）で基本的な動作をあてる
- リップシンク: uLipSync（無料）や Oculus Lipsync

HMD で歩き回る段になったら、ここで初めて XR Interaction Toolkit と OpenXR が必要になる
（`SimpleWalker` を XR Origin に置き換える）。

**先に②や④で 3D をやろうとしないこと。**
対話シナリオで 3D アバターを作り込んでも、学習効果はほとんど上がらない。

## 音声について

見た目より**音声のほうが効く**。同じ予算なら、3D モデルより音声収録を優先する。

- 台詞の読み上げ（声の震え、間、語尾）は、対話訓練の手がかりそのもの
- 合成音声（VOICEVOX 等）でも、無音よりはるかに良い
- ③ の夜勤はアラーム音・ナースコール音が緊迫感を作る。効果音は安価で効果が大きい

## 法的・倫理的な注意

- **実在の患者を撮影・録音しない。** 模擬患者か俳優を使う
- 撮影した人物の**肖像の利用範囲を書面で合意する**（研修内のみか、公開可か）
- 医療機関で撮る場合、背景の掲示物・カルテ・名札・他の患者の写り込みを確認する
- **登場人物の描写を、特定の属性と結びつけない。**
  「虐待をする親はこういう見た目」「精神的に不安定な人はこういう外見」という
  誤ったスキーマを、映像は文章よりはるかに強く刷り込む。
  ⑤ については特に、外見に手がかりを持たせない方針を徹底する
- 生成 AI で人物画像を作る場合、実在の人物に似ないか、学習データの権利関係が
  問題にならないかを確認する

## 順序についての意見

見た目は、**文言が監修者のレビューを通ってから**着手することを勧める。

いまの 5 本はいずれも監修前の仮版で、台詞も選択肢も変わる。
360度実写は分岐の数だけ撮影が必要なので、文言が変わるたびに撮り直しになる。
2D 背景 + 立ち絵なら差し替えが即日で済むため、監修と並行して進められる。

現実的な順序:

```
1. いまの 5 本を実務者にレビューしてもらい、文言を確定させる
2. 並行して 2D 背景 + 立ち絵で見た目を整える（SimBackdrop）
3. 音声を収録する
4. 文言が固まったら、①②④⑤ を 360度実写に置き換える
5. 予算と必要性を見て、③ を 3D 化する
```
