# 単体版シナリオ

シナリオ 1 つが 1 フォルダで完結する形。**他のフォルダに一切依存しない**ので、
入れるのも消すのも 1 フォルダ単位で済み、他のシナリオを巻き込んで壊れることがない。

`codemed-x/unity/Assets/CodemedX`（共通基盤）とは独立している。
両方をプロジェクトに入れても衝突しないが、**どちらか一方だけで完結する**。

## なぜ 2 つの作り方があるのか

| | 単体版（このフォルダ） | 共通基盤版（`unity/Assets/CodemedX`） |
|---|---|---|
| 依存 | なし。1 フォルダで完結 | 共通のアセンブリを全シナリオが共有 |
| 導入 | フォルダを 1 つ置くだけ | 基盤を先に入れる必要がある |
| 壊れ方 | そのシナリオだけが壊れる | 基盤が壊れると全部止まる |
| コード | シナリオ間で重複する | 重複しない |
| 向き | まず 1 つ動かす、個別に配る | 5 本を同時に育てる |

**共通しているのは学習履歴の形だけ**。どちらで作っても
`TrainingEvent` のフィールドは同じなので、LMS やスプレッドシート側は
1 種類の受け口で 5 テーマすべてを受けられる。ここだけは崩さないこと。

## ① 相談援助面接（児童相談所の家庭訪問）

`01-welfare-interview/` — **実装済み。そのまま動く。**

### 動かし方

1. Unity プロジェクトの `Assets/` の下に `01-welfare-interview` フォルダをコピーする
2. 適当なシーンで **GameObject > Create Empty**
3. 作った GameObject に `WelfareInterviewSim` スクリプトをドラッグして付ける
4. **Play** を押す

Canvas も Prefab も XR パッケージも要らない。画面は IMGUI（`OnGUI`）で描いているので、
シーンの準備なしで Game ビューに操作画面が出る。

### 中身

| ファイル | 役割 |
|---|---|
| `WelfareInterviewSim.cs` | 局面の進行と画面。触るのはまずここ |
| `WelfareScenarioData.cs` | 文言・配点などの中身。**監修者が直すのはここだけ** |
| `WelfareTrainingLog.cs` | 学習履歴の記録（Console + 端末内ファイル） |

### 進行

```
1. 事前確認   通告受理票と資料を読む（読まずに訪問すると記録される）
2. 観察       家の中で気になったものを見る。リスクサインと中立な物が混ざっている
3. 面談       拒否的な保護者との対話。信頼度は面談中には表示しない
4. 判断       一時保護（児童福祉法第33条）の要否と、その根拠を選ぶ
5. 報告       上司への報告に含める要素を選ぶ
6. 振り返り   スコア、見落とし、信頼度の推移、ログの保存先
```

### 設計上こだわった点

- **見落としを明示的に記録する。** 観察フェーズを抜けるとき、未確認のリスクサインを
  `ObservationMissed` として記録する。「イベントが飛んでこない＝見落とし」にすると、
  通信欠損と区別が付かない。
- **信頼度を面談中に見せない。** 数値が見えると、相手の反応ではなく数値を見て
  操作する練習になってしまう。振り返りで初めて開示する。
- **判断と根拠を分けて取る。** 結論だけ合っていて根拠が伴わない場合を区別するため。
- **根拠にならない選択肢を混ぜてある。** 「態度が非協力的」「金銭の使い方」は
  法的要件の根拠にならない。選ぶと減点され、理由が振り返りに出る。

### 学習履歴

`Application.persistentDataPath` に JSON Lines で保存される（保存先は振り返り画面に表示）。
Windows なら概ね `C:\Users\<ユーザー名>\AppData\LocalLow\<会社名>\<プロジェクト名>\`。

1 行が 1 イベントで、形式は
[`codemed-x/schema/training-event.schema.json`](../schema/training-event.schema.json) と同じ。
`objective_id`（`WLF-*`）は [`codemed-x/schema/objectives.csv`](../schema/objectives.csv) を介して
医学教育モデル・コア・カリキュラム（令和4年度改訂版）の id に対応している。

### 内容についての注意

`WelfareScenarioData.CreateDefault()` の題材は**監修前の仮版**。構造を体験するための
たたき台であり、実際の研修に使う前に児童福祉の実務者のレビューを必ず受けること。
文言はすべて `WelfareScenarioData.cs` の 1 箇所にまとまっているので、
C# を書かずに差し替えられる。

## ②〜⑤

いずれも①と同じ 3 ファイル構成。**すべて実装済みで、そのまま動く。**
入れ方は①と同じ（フォルダを `Assets/` に置き、空の GameObject にスクリプトを付けて Play）。

### ② 困難な対話（ACP / SPIKES）— `02-acp-dialogue/`

付けるスクリプト: `AcpDialogueSim`

膵臓がんの患者本人（治療中止を希望）と長男（延命を希望）が同席する面談。
SPIKES の 6 ステップを進みながら、双方との関係を保って方針を作る。

- 選択肢は患者と家族に**非対称に**効く。片側だけを見て対応すると両方を失う
- 家族の不安が 80 を超えると激高状態に入り、以降は患者の信頼にも負の副作用が出る
- 悪い知らせの直後に沈黙の場面がある。4 秒待てたかどうかを測る（待つことは強制しない）
- ステップを飛ばすボタンがある。飛ばしても進むが記録される
- 患者・家族の 3 つのパラメータは対話中は非表示

### ③ 夜勤・複数患者の優先順位判断 — `03-nightshift-triage/`

付けるスクリプト: `NightShiftSim`

5 本のうちこれだけが**実時間で進む**（180 秒）。10 秒で SpO2 低下、30 秒で抜管リスク、
60 秒で事務電話、90 秒でナースコール同時点灯。

- より緊急なタスクを差し置いて着手すると優先順位の逆転として記録される
- 許容時間を超えて放置すると重大化する（状態悪化・自己抜管）
- **急変から医師への報告までの秒数**が最重要指標。振り返りで単独の数値として出る
- 最後まで報告しなかった場合も明示的に減点する

**③ だけは 3D の病棟を歩き回る版がある**（[docs/visuals.md](../docs/visuals.md) の判断どおり、
移動と複数患者の同時把握が学習内容そのものだから）。

| ファイル | 役割 |
|---|---|
| `SimpleWalker.cs` | 一人称移動。PC は WASD + マウス、タブレットは `TouchControls` の仮想パッドを読む |
| `TouchControls.cs` | タブレット用の仮想パッド（画面左ドラッグ＝移動、右ドラッグ＝視点） |
| `BedStation.cs` | ベッド・電話・ナースコール共通の「近づいて [E]／タップで対応する」部品 |
| `NurseStationPhone.cs` | 医師への疑義照会（エスカレーション）用の電話 |
| `Editor/NightShiftHospitalBuilder.cs` | グレーボックス病棟をメニュー 1 つで生成（`TouchControls` の配線も自動） |

使い方:

1. 空のシーンで **Tools > Codemed-x > 夜勤: グレーボックス病棟を生成**
2. Play。
   - **PC**: WASD + マウスで歩き、ベッドや電話に近づいて **[E]** で対応する
   - **タブレット**: 画面の左半分をドラッグで移動、右半分をドラッグで視点。
     近づくと出る「[E] 対応する」のボタンはタップで押せる

`TouchControls` はタッチに対応した端末（`Input.touchSupported`）でだけ仮想パッドを描く。
PC では何も表示・入力しないので、同じシーンのまま両方の端末に配れる。

生成されるのは灰色の板だけの仮モデル。判定・スコア・ログは
IMGUI 版とまったく同じ `NightShiftSim` の API（`TryAttendTo` / `TryOpenEscalationMenu`）を
経由するため、**3D にしたことで採点基準が変わることはない**。
本物のモデルに差し替えるときも `BedStation` / `NurseStationPhone` はそのまま使え、
見た目（Cube のメッシュとマテリアル）だけを入れ替えればよい。

3D 版では `NightShiftSim` の **Compact Hud** が入る（ビルダーが自動で入れる）。
勤務中の画面が左上の小さな表示だけになり、病室が隠れなくなる。

- 左上に出るのは「残り秒数・発生中のタスク・各タスクの経過秒」だけ
- 着手はベッドのランプに近づいて **[E]**、医師への電話は青い電話に近づいて **[E]**
- 電話をとると SBAR の選択画面が中央に出る。この間は**マウスカーソルが解放され、
  視点操作が止まる**（選択肢を押そうとして視点が回るのを防ぐため）
- 説明（Briefing）と振り返り（Debrief）は読ませたいので全画面のまま

**Compact Hud のチェックを外せば、3D のシーンでも従来どおり全画面のボタン UI で
最後まで進められる。** VR 酔いや PC 環境への配慮が要る学習者には、
歩かずキーボードだけで完結するこちらを配ればよい。

### ④ 薬剤師：服薬指導から疑義照会 — `04-pharmacist-inquiry/`

付けるスクリプト: `PharmacistInquirySim`

NSAIDs と ACE 阻害薬を併用中の高齢者。患者の「足がむくむ」という訴えから
腎機能低下に気づき、多忙な医師へ疑義照会する（薬剤師法第24条）。

- 服薬指導 → 検査値の添付 → 電話 の連鎖。どこかが欠けると医師を説得できない
- 検査値には無関係な項目も混ぜてある。関係ない値を添付すると減点
- 電話には**応答制限時間（10 秒）**がある。黙っていると圧力が上がる
- 医師のプレッシャーが 80 に達すると電話が切られる。値は会話中は非表示
- 自分から引き下がると `YieldedToAuthority`。**このシナリオで最も重要な失敗**

### ⑤ ゲートキーパー：自殺リスク評価と危機介入 — `05-gatekeeper/`

付けるスクリプト: `GatekeeperSim`

地域の相談窓口。顔なじみの相談者の様子が違う。気づき・傾聴・つなぎ・見守り。

- 「死にたいと考えていますか」の選択肢は**常に画面に出したまま**にしてある。
  信頼が足りなければ時期尚早として記録されるが、傾聴を重ねて尋ね直せる
- 最後まで尋ねなかった場合は `RiskAssessmentIncomplete`。
  **尋ねないことは安全な選択ではなく、不作為の誤りとして扱う**
- 安易な励ましは信頼を下げ、同時に**切迫度を上げる**。切迫度は最後まで非表示
- 相談窓口の案内を全局面に常設し、中断ボタンを常時置いている

## 背景と登場人物を付ける

`presentation/SimBackdrop.cs` を使うと、**シナリオ側のスクリプトを変更せずに**
背景画像と立ち絵を後ろに描ける（IMGUI の描画順を後ろに回している）。

1. シーンに空の GameObject を作り、`SimBackdrop` を付ける
2. `Background` に背景画像、`Characters` に立ち絵を割り当てる
3. 文字が読みにくければ `Dim Amount` を上げる

素材が無くても、灰色の板でレイアウトだけ先に決められる。
どの作り方（2D / 360度実写 / 3D）を選ぶかは
[`docs/visuals.md`](../docs/visuals.md) を参照。

### 場面が変わったら背景も変える

`SimBackdrop` の **Phase Backgrounds** に「局面名 + 背景画像」を並べる。
局面が変わると自動で切り替わり、`Cross Fade Seconds` の秒数でフェードする。

局面名は各シナリオの `Phase` の名前をそのまま書く。

| | 局面名（この文字列をそのまま入れる） |
|---|---|
| ① 相談援助面接 | `Preparation` / `Observation` / `Interview` / `Assessment` / `Escalation` / `Debrief` |
| ② 困難な対話 ACP | `Briefing` / `Dialogue` / `Debrief` |
| ③ 夜勤 | `Briefing` / `Shift` / `Debrief` |
| ④ 疑義照会 | `Counseling` / `LabReview` / `DoctorCall` / `Debrief` |
| ⑤ ゲートキーパー | `Briefing` / `Dialogue` / `Closing` / `Debrief` |

一致する行が無い局面では `Background`（既定の背景）に戻る。
全局面で同じ背景でよければ `Phase Backgrounds` は空のままでよい。

登場人物も局面で出し入れできる。`Characters` の各要素の
**Visible In Phases** に局面名をカンマ区切りで書くと、その局面でだけ表示される
（空なら全局面）。④で「電話の場面だけ医師を出す」なら `DoctorCall` と書く。

**シナリオ側のスクリプトは何も変えなくてよい。**
`SimBackdrop` は同じシーンから `CurrentPhaseName` を持つスクリプトを自動で探す。
1 シーンに複数のシナリオを置いている場合だけ、`Phase Source` に対象を明示的に割り当てる。

### 360度画像を使う場合

`presentation/` の中身は 3 つ。

| ファイル | 役割 |
|---|---|
| `SimBackdrop.cs` | **2D** の背景 + 立ち絵を IMGUI で描く |
| `PanoramicBackdrop.cs` | **360度**画像（Skybox）を局面ごとに切り替える |
| `PhaseWatcher.cs` | 「いまどの局面か」をシナリオ側に依存せず読み取る共通部品 |

**360度画像を `SimBackdrop` に割り当てないこと。** 球に貼る前提の絵（横縦比 2:1）を
平面に描くので端が歪む。360度は `PanoramicBackdrop` を使い、
シーンに Camera を置いて `Clear Flags` を `Skybox` にする。

2D と 360度のどちらで進めるかは
[`docs/visuals.md`](../docs/visuals.md) の「①②④⑤ は 2D か、360度のままか」を参照。

## 1 シーンで動かせるのは 1 つだけ

5 つの GameObject を同時に有効にすると、それぞれが**全画面 UI を描いて重なり**、
どれも操作できなくなる。切り替え方は 2 つ。

**A. チェックボックスで切り替える（手軽）**

同じシーンに 5 つ置いておき、動かしたいもの以外を Inspector の
コンポーネント名の左にあるチェックボックスで無効にする。Play し直すと切り替わる。

**B. シナリオごとにシーンを分ける（おすすめ）**

`File > New Scene` で 5 つのシーンを作り、それぞれに 1 つずつ置く。
演習で 1 本ずつ配る運用にもそのまま乗る。

**C. ランチャーで 1 つにまとめる（ブラウザで配るならこれ）**

`00-launcher/ScenarioLauncher.cs` を使うと、5 つのシーンへの入り口となる
メニュー画面を 1 つ作れる。ブラウザ（WebGL）で 1 つの URL を配りたい場合はこちら。
手順は [`docs/webgl-deploy.md`](../docs/webgl-deploy.md) を参照。

事故防止として、**先に起動した 1 本だけが動く**ようにしてある。
2 つ目以降は自動的に待機し、Console に次の警告が出る。

```
[Codemed-x] 別のシナリオが実行中のため XxxSim は待機します。
```

この警告が出ていたら、動かしたいシナリオ以外を無効にして Play し直す。

## 日本語が □ になる場合

各シナリオのスクリプトの Inspector に **Ui Font** の欄がある。
日本語を含むフォント（例: Windows の `meiryo.ttf`）をプロジェクトに取り込んで割り当てる。
多くの環境では未設定のままでも表示される。

**WebGL では未設定のままだと確実に □ になる。** ブラウザには OS のフォントへ
フォールバックする仕組みが無いため、必ず日本語フォントを `Ui Font` に割り当てる。
詳しくは [`docs/webgl-deploy.md`](../docs/webgl-deploy.md) を参照。

## ブラウザ・タブレットで使ってもらう

PC のブラウザや iPad の Safari から使ってもらうには、Unity の **WebGL ビルド**にする。
初めてでも迷わないよう、Build Settings の設定からホスティングまでを
[`docs/webgl-deploy.md`](../docs/webgl-deploy.md) に手順化した。
